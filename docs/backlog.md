## 计划中的工作

| 项目 | 说明 | 可行性 |

| 审批记忆 | 同一回合内针对完全相同的审批请求（同一工具、同一参数）沿用上一次决定，减少反复点击 | 桥接侧可实现。DSH 的审批粒度只有 `allowed-once` 与 `rejected`，因此这等于替用户作出安全决定，必须显式开启且范围受限 |

- **真机验证。** 已验证：markdown 渲染（A2/B2 对照，见[设计与实现说明](design-notes.md)）、表格改写、`/find` 的实际搜索、重复消息去重、按钮化提问。尚未记录到一次完整通过：`/doctor` 的首次实跑、`/todos`、中文快捷词与 `/` 下拉面板在群聊中的表现。
- **发布流程的一处约束（已完成，留作记录）。** 仓库的 deploy key **无法推送** `.github/workflows/` 下的文件，GitHub 会以缺少 `workflow` 权限拒绝；解决办法是临时把一把密钥加为**账号级 SSH key**（用户身份可以推送），发版后删除。设备流无法在本机完成，因为本机到 `github.com:443` 不通，仅 SSH 可用。

## 已知问题

**provider 偶发 400：`The reasoning_content in the thinking mode must be passed back to the API`**（Console Go 路由）。表现为 agent 回合失败，并把错误原文转发到 QQ。同一会话的后续回合正常，因此判断与**历史被改写**有关：该会话的上下文曾发生压缩，而压缩会重写助手回合并丢掉 `reasoning_content`，该 provider 在 thinking 模式下要求原样回传。

复发时的绕法是 `/new` 开新会话，或用 `/model` 换到非 thinking 的路由。根治在适配器或 provider 一侧，不在本桥接。`agent/error` 现在也会写入 `/log`，便于下次定位。

## 待决定

- **套餐窗口告警。** 是否在 5 小时 / 本周 / 本月额度接近上限时提醒一次，与余额告警同理。数据现成，成本小。
- **用户可见文案的语言。** 代码注释已英文化，剩余的语言缺口在面向用户的文案：插件回复为中文硬编码。可选方向：(a) 维持现状；(b) 把面向用户的文案抽出为可替换的语言包；(c) 增加英文回复。
- **CI 运行平台。** 目前仅在 `windows-latest` 上运行，覆盖 Node 22 与 24。可选方向：(a) 保持仅 Windows，完全贴合真实环境；(b) 增加 ubuntu 矩阵以获得更好的覆盖，但 ubuntu 未在本地验证。
